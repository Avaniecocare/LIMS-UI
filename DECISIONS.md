# Decisions

- **TypeScript 5.9 here.** `openapi-typescript` does not accept TypeScript 6 yet.
- **TanStack Table v8.** Pinned to the v8 API.
- **Native `<select>` for master lists.** It is fast on long lists and works well with keyboards and tablets; Radix menus are used for action menus only.
- **List state lives in the URL,** so filters survive reloads and saved filters are just stored parameters.
- **The CSRF token is held in memory** and refetched from `/auth/me` on reload. Nothing sensitive goes in browser storage.
- **`style-src 'unsafe-inline'` in the CSP.** Radix and Recharts set inline styles. Scripts stay strict: `script-src 'self'`, with runtime config in a same-origin file.
- **Text colour on brand surfaces is computed** from the brand colour's luminance, so any company's colours keep readable contrast.
- **Document tabs open during the click.** Workers can take longer than the browser's popup allowance, so the tab is reserved first and pointed at the signed link when it is ready. If the tab is blocked, a toast offers the link instead.
- **Scanner detection uses event timestamps,** not arrival order: a burst of at least 4 characters under 30 ms apart, ending in Enter, with no field focused. Typing in a field is never intercepted.
- **Customer and job pickers search on the server** rather than loading a capped option list, since those lists have no practical upper size.
- **Autosave is a plain queue, not a hook.** `features/testing/autosave.ts` runs one save at a time and sends the version the last one returned, so it can be unit-tested with fake timers and versions cannot race.
- **Half-typed numbers are not sent.** The field is checked for format in the browser and flagged, so typing `5x` on the way to `5.2` does not cost a round trip. All arithmetic stays on the server.
- **An entry the server refuses stays on its input.** `PUT /tests/{id}/results` answers 400 `RESULT_INVALID` with the parameter ids in `fields[].field`, and refuses the whole save. The message goes on that input, what was typed stays, and everything else in the save is sent again without it.
- **Who may start a test comes from `assignedToMe`,** which the server works out from the assignee's id.
- **The Review tab is two tables.** `GET /reports` takes one status at a time, and merging two paged lists in the browser would give wrong pages.
- **`/` has no charts; `/analytics` does.** The dashboard is My work and a summary of tiles, so most people, and every technician, never download Recharts. It is imported only from `features/dashboard/charts.tsx`, which is lazy.
- **Every chart has a table view.** SVG bars are not keyboard reachable, so each chart is labelled as an image with its numbers in words, and its Table button shows the same points as real links.
- **A dashboard link the user cannot follow shows as a plain number.** Links come from the server without regard to the role: a reviewer's rejection rate links to a report that needs `mis.view`, and an approvals link falls back to another tab. `features/dashboard/links.ts` checks the page's permission and the report catalog.
- **Some dashboard counts cannot match the list they link to,** because the list has no matching filter. "Urgent jobs open" excludes completed and cancelled jobs, while `/samples?urgent=true` lists them all. "On hold" adds on-hold jobs to on-hold tests, while `/samples?status=ON_HOLD` lists jobs. "Revisions issued" counts the period's revisions, while `/approvals?tab=issued` lists every issued report. The UI shows the server's number and link unchanged. The full-cycle test compares only the counts that link to reports.
- **Money on a payment form is not added up.** "No summing money in the browser" rules out a running "left as an advance" figure, so the form explains the rule and the confirmation shows the `unapplied` the server returns.
- **Report pages have no search or sorting.** `GET /mis/{key}` accepts `q` and `sort` but ignores them, so offering them would do nothing.
- **Bare report links get the current month; other links do not.** A dashboard link such as `/reports/sample-status?status=RECEIVED` counted all dates, so adding a default range would make it disagree with its number.
- **Errors are reported through a hook, not a vendor.** `lib/error-reporting.ts` sends nothing until `setErrorReporter` is called. It strips emails, ids, query strings and anything shaped like a secret first. The router catches errors in routes before a React boundary can, so routes use `errorElement` and the rest of the app a class boundary.
- **Chart colours are fixed, not the brand's.** A company's brand colour can be anything, while chart colours must keep their contrast and colour-blind separation. They were checked with a palette validator.
- **The CI backend runs migrations in the API container's start command.** The API cannot boot without its schema, and the seed needs the roles the API creates on first start, so the seed runs afterwards with `docker compose exec`.
- **The report verification page needs no sign-in and checks PDF copies in the browser.** `/verify/:code` sits outside the signed-in routes, so it opens on any phone. Choosing a PDF hashes it with Web Crypto and compares it with the issued file's SHA-256, so the file never leaves the device. A printed copy can't be hashed, so the page lists the results for comparison.
- **Forms fill themselves where the system already knows the answer.** GSTIN fills state, GST code and PAN; a PIN code fills city, state and GST code and offers post office names for line 2; the state field suggests the official state names and sets the GST code; a new quotation takes the signed-in user as contact and the customer's credit days as payment terms. Every filled value stays editable.
- **The customer page is the customer's history.** Tabs (overview, quotations, jobs, tests booked, reports, invoices and payments, files, details, activity) appear only for people who may see their contents, and each loads when opened.
- **Files** is one screen for the lab's documents (folders, upload by drag and drop, rename, move, remove with a reason) and a read-only view of the files the system made. The same list, fixed to one customer, is that customer's Files tab.

- **Dark mode re-maps tokens instead of adding `dark:` classes.** Greys, status tints and the brand colour are CSS variables, swapped under `html[data-theme='dark']`, so every screen follows without per-component changes. The choice is a display preference in `localStorage`; the lab's colours are lightened for dark surfaces in `applyBranding`. axe checks every main screen in both themes.
- **Motion is a small set of tokens and utilities** (`docs/design-system.md`): transform and opacity only, 140–320 ms, nothing that blocks input, all of it off under reduced motion except spinners. Page fades use the Web Animations API on the content area, so pages are never re-mounted for an effect.
- **The dashboard counts up over the real value.** The counting digits are an `aria-hidden` overlay; the true figure is always in the page for screen readers, copying and tests.
- **A phone is below 768 px; what it shows is decided in `app/device.ts`.** Tablets get the full app. Desktop-only screens show "Best on a larger screen" with Continue anyway, never a dead end.
- **Phone tables are cards from the same column definitions,** so no screen needs a second layout. The first four named columns show; the rest are under More details.
- **The service worker only serves an offline page.** Caching pages or API responses would keep lab data on phones and delay releases; neither is worth it for an app that needs the server anyway.
