This is the full reference. Variables are listed by **name and purpose** only. Never put real values in tickets, chat or documentation.

Only server settings belong in the environment, plus `BRAND_NAME`. Everything about the laboratory itself (name, legal details, GSTIN, bank account, NABL details, logo, colours, email wording, which modules are on) is set by the lab's administrator in the app and stored in the database. See [Settings](/help/admin/settings/).

## How settings reach the app

- **With the deployment scripts:** you edit `deployment.env` in the company folder. `provision.sh` generates `secrets.env`. On every deploy the scripts write `generated.env` for the API and worker, and `migrate.env` for the one-off migration container. Do not edit `generated.env` or `migrate.env` by hand: they are rewritten.
- **Without the scripts:** the API and worker read their own environment (for example a `.env` file passed with `node --env-file=.env`).

The API and worker check their settings when they start. A missing or invalid value stops the process with **exit code 78**, and the message names the variable but never its value.

:::note
The deployment scripts pass only the variables listed in `generated.env` to the API and worker. A variable in the tables below that the scripts do not set takes its default.
:::

Quote values that contain `#` or spaces, for example `SMTP_FROM="lab@example.com"`. In `deployment.env`, double-quote every value.

## Core

| Name | Required | Default | What it does |
| --- | --- | --- | --- |
| `BRAND_NAME` | No | `LIMS` | The product name shown until the administrator sets the lab's own name and app name. The only branding value in the environment. |
| `NODE_ENV` | No | `development` | Set `production` on servers. Production refuses the public example session secret and makes the cookie secure by default. |
| `PORT` | No | `3000` | Port the API listens on. |
| `LOG_LEVEL` | No | `info` | Log detail: `fatal`, `error`, `warn`, `info`, `debug` or `trace`. |
| `TRUST_PROXY` | No | `false` | Set `true` behind a reverse proxy or load balancer, so client addresses and HTTPS are read correctly. The deployment scripts set `true`. |
| `FRONTEND_ORIGIN` | **Yes** | None | Where people open the app, for example `https://app.lims.example.com`. Used in emails, in the QR verification links printed on reports and in phone-upload links. Requests from any other origin are refused. |
| `PUBLIC_API_URL` | No | `http://localhost:<PORT>` | Where browsers reach the API, for logos and file links. Meta's WhatsApp webhook also calls this address. |

## Database (PostgreSQL)

| Name | Required | Default | What it does |
| --- | --- | --- | --- |
| `DATABASE_URL` | **Yes** | None | PostgreSQL connection address. In the deployment, the `lims_app` role, which cannot change tables. |
| `DATABASE_READ_URL` | No | None | A read replica, used for reports and dashboards. |
| `DATABASE_POOL_SIZE` | No | `10` | Database connections per process. |
| `MIGRATION_DATABASE_URL` | Deployment only | None | The table-owner (`lims_owner`) address. Written to `migrate.env` and loaded only by the migration container. |

PostgreSQL 16 or later is needed. The deployment runs PostgreSQL 18.

| `MAX_UPLOAD_BYTES` | No | `15728640` (15 MB) | Largest file upload accepted. |

See [Storage](/help/integrations/storage/).

## Sessions and security

| Name | Required | Default | What it does |
| --- | --- | --- | --- |
| `SESSION_SECRET` | **Yes** | None | At least 32 random characters, unique per installation. Signs the session store keys. Production refuses the public example values. Generated by `provision.sh`. |
| `SESSION_IDLE_MINUTES` | No | `30` | A session ends after this many minutes without activity. |
| `SESSION_MAX_HOURS` | No | `12` | A session ends this many hours after sign-in, however active. |
| `SESSION_COOKIE_NAME` | No | `lims_sid` | Name of the session cookie. |
| `SESSION_COOKIE_DOMAIN` | No | None | Cookie domain, if it must cover more than the API host. |
| `COOKIE_SECURE` | No | `true` when `NODE_ENV=production`, otherwise `false` | Send the cookie over HTTPS only. Always `true` when served over HTTPS. |
| `SETUP_TOKEN` | No | None | When set, the first-run screen asks for this token before anyone can create the first administrator. Recommended for any install reachable from the internet. `provision.sh` always sets one. |

See [Authentication](/help/developers/authentication/) for how sessions work.

## GST e-invoicing

| Name | Required | Default | What it does |
| --- | --- | --- | --- |
| `EINVOICE_PROVIDER` | No | None | `nic` registers at the government IRP's direct API. `mock` makes test IRNs on this server, for training (printed as TEST). Unset means e-invoicing is not set up. |
| `EINVOICE_ENV` | No | `sandbox` | `sandbox` or `production`. `mock` is refused with `production`. |
| `EINVOICE_BASE_URL` | In the sandbox | `https://api.einvoice1.gst.gov.in` in production | The IRP address. The sandbox address is shown after signing in to einv-apisandbox.nic.in. |
| `EINVOICE_CLIENT_ID`, `EINVOICE_CLIENT_SECRET` | With `nic` | None | From the e-invoice portal's API registration. |
| `EINVOICE_USERNAME`, `EINVOICE_PASSWORD` | With `nic` | None | The API user created on the e-invoice portal. |
| `EINVOICE_GSTIN` | With `nic` | None | The lab's GSTIN the API user belongs to. Must match the Lab profile. |
| `EINVOICE_PUBLIC_KEY` | With `nic` | None | The IRP's public key in PEM form. Line breaks may be written as `\n`. |

With `nic`, a missing setting stops the server at start, naming it. The credentials are never shown in Admin or sent to a browser. See [GST e-invoicing](/help/integrations/e-invoicing/).

## AI help assistant

The help site's **Ask AI** assistant answers questions from the published documentation, through the API. It is off unless you turn it on.

| Name | Required | Default | What it does |
| --- | --- | --- | --- |
| `ENABLE_AI_ASSISTANT` | No | `false` | `true` turns the assistant on, if a usable provider is set. Otherwise the help site offers search only. |
| `AI_PROVIDER` | No | `anthropic` | Which AI service answers. `mock` gives an offline answer for development and tests. |
| `AI_API_KEY` | When on | None | API key for the AI provider. Without it (and without `mock`), the assistant stays off. |
| `AI_MODEL` | No | `claude-haiku-5-5` | Model name to use. |
| `EMBEDDING_PROVIDER` | No | `none` | `voyage` adds vector search of the docs (Voyage AI). `none` uses keyword search only, all on your server. |
| `EMBEDDING_API_KEY` | No | None | API key for the embedding service. |
| `EMBEDDING_MODEL` | No | `voyage-3.5-lite` | Embedding model name. |
| `HELP_INDEX_URL` | No | `<FRONTEND_ORIGIN>/help/help-index.json` | Where the API reads the docs search index built with the help site. |
| `HELP_INDEX_PATH` | No | None | A file path to read the index from instead of a URL. |
| `RATE_LIMIT_PER_MINUTE` | No | `10` | Questions allowed per visitor per minute. |
| `RATE_LIMIT_PER_DAY` | No | `50` | Questions allowed per anonymous visitor per day. |
| `SIGNED_IN_RATE_LIMIT_PER_DAY` | No | `200` | Questions allowed per signed-in user per day. |
| `DAILY_BUDGET_LIMIT` | No | `1` (US dollars) | The assistant turns itself off for the rest of the day when this spend is reached. |
| `MONTHLY_BUDGET_LIMIT` | No | `20` (US dollars) | The assistant turns itself off for the rest of the month when this spend is reached. |
| `MAX_QUESTION_LENGTH` | No | `500` characters (at most 2000) | Longest question accepted. |
| `MAX_OUTPUT_TOKENS` | No | `800` (at most 4000) | Longest answer the model may write. |
| `TURNSTILE_SITE_KEY` | No | None | Cloudflare Turnstile site key, to challenge anonymous visitors. |
| `TURNSTILE_SECRET_KEY` | No | None | Cloudflare Turnstile secret key. |
| `AI_REQUIRE_LOGIN` | No | `false` | `true` lets only signed-in staff use the assistant. |
| `ALLOWED_ORIGINS` | No | The app's own origin | Comma-separated extra origins (for example a separately hosted help site) allowed to call the assistant. The app's origin is always allowed. |
| `HELP_SUPPORT_EMAIL` | No | None | Support address the assistant can point people to. |
| `HELP_LOG_RETENTION_DAYS` | No | `90` | Days the anonymous question log is kept. |

With LIMS-Deploy, set these in `deployment.env`; `scripts/lib/common.sh` passes each one to the API, and an empty value means the default. See [AI help assistant](/help/integrations/ai-assistant/).

## Older installs: `COMPANY_*`

Versions before the admin panel read the lab's details from `COMPANY_*` variables (or a `company.env` file in the deployment). If they are present when the lab profile is still empty, they are checked and imported into the admin panel once, logo and favicon included, and the setup wizard is skipped. After that they are ignored and can be removed. A new install should not set them.

## UI container

The same UI image serves every company. It reads these when the container starts.

| Name | Required | Default | What it does |
| --- | --- | --- | --- |
| `API_URL` | **Yes** | None | The API address browsers call, for example `https://api.lims.example.com`. Written into the runtime `config.js` and allowed in the page's Content Security Policy. The container stops (exit 78) if it is missing or contains a quote, backslash or `<`. |
| `STORAGE_ORIGIN` | No | Empty | The files domain, for example `https://files.lims.example.com`. Allowed in the Content Security Policy, so signed images and PDFs can show in the app. |
| `APP_NAME` | No | `Laboratory` | The app's name when installed on a phone's home screen. The first 12 characters become the short name. The deployment sets it from `BRAND_NAME`. When set, it is also the name in the help site's title. |
| `APP_URL` | No | None | The app's own address, for example `https://app.lims.example.com`. Used for the help site's page addresses and sitemap. The container stops (exit 78) if it is not a plain `http` or `https` address. |

## `deployment.env`

These are read by the deployment scripts and Compose, not by the app directly.

| Name | Required | Default | What it does |
| --- | --- | --- | --- |
| `BRAND_NAME` | No | `LIMS` | Passed to the app as `BRAND_NAME` and to the UI as `APP_NAME`. |
| `CLIENT_SLUG` | **Yes** | None | Lowercase letters, digits and hyphens. Names the Compose project (`lims-<slug>`), containers and volumes. |
| `APP_DOMAIN` | **Yes** | None | The web app's domain. |
| `API_DOMAIN` | **Yes** | None | The API's domain, under the same parent domain as `APP_DOMAIN`. |
| `FILES_DOMAIN` | **Yes** | None | The storage domain, for short-lived signed links. |
| `S3_IMAGE` | **Yes** | None | The S3-compatible storage image, pinned to an exact version. Must keep data in `/data` and listen on port 9000. |
| `S3_COMMAND` | No | `server /data` | The storage container's command, for an image that needs a different one. |
| `S3_HEALTHCHECK_CMD` | No | Built-in probe | Health check for the storage container, if the image has none of curl, wget, node or nc. |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`, `SMTP_TRANSPORT` | Host, port, secure and from: **Yes** | None | Passed to the app. See [Email](#email-smtp). |
| `DATABASE_READ_URL` | No | None | Passed to the app. |
| `ERROR_TRACKING_DSN` | No | None | Passed to the app. |
| `WHATSAPP_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID`, `WHATSAPP_APP_SECRET`, `WHATSAPP_VERIFY_TOKEN` | No | None | Passed to the app. |
| `SESSION_MAX_HOURS` | No | `12` | Passed to the app. |
| `PINCODE_LOOKUP_URL` | No | India Post's directory | Passed to the app. Set `""` to turn the lookup off. |
| `POSTGRES_MEM_LIMIT` | No | `512m` | Memory cap for PostgreSQL. |
| `REDIS_MEM_LIMIT` | No | `128m` | Memory cap for Redis. |
| `S3_MEM_LIMIT` | No | `256m` | Memory cap for storage. |
| `API_MEM_LIMIT` | No | `768m` | Memory cap for the API. |
| `WORKER_MEM_LIMIT` | No | `1g` | Memory cap for the worker. Raise this first if large PDFs fail. |
| `UI_MEM_LIMIT` | No | `64m` | Memory cap for the UI. |
| `BACKUP_RETENTION_DAYS` | No | `30` | Local backups older than this are deleted after a good backup. |
| `BACKUP_AGE_RECIPIENT` | No | None | Encrypt backups to one or more age public keys (space-separated). Recommended. |
| `BACKUP_GPG_RECIPIENT` | No | None | Encrypt backups to a gpg public key in the backup user's keyring. |
| `BACKUP_GPG_PASSPHRASE_FILE` | No | None | Symmetric gpg encryption, with the passphrase in this file (mode 600). Also used to decrypt on restore. |
| `BACKUP_AGE_IDENTITY_FILE` | Restore only | None | The age private key file, on the machine that restores. Keep it off the server otherwise. |
| `BACKUP_OFFSITE_CMD` | No | None | Command run after each nightly backup to copy it off-site. Use single quotes. |
| `BACKUP_OFFSITE_ALLOW_PLAINTEXT` | No | `false` | `true` allows off-site copies of unencrypted backups. |
| `BACKUP_PING_URL` | No | None | Fetched after every fully successful backup, for a dead-man's-switch alert. |

The memory caps also apply to the proxy: `CADDY_MEM_LIMIT` (default `128m`), set where you start the proxy.

### `versions.env`

| Name | Required | What it does |
| --- | --- | --- |
| `LIMS_VERSION` | **Yes** | Exact version of the backend image (API, worker and migrations). |
| `LIMS_UI_VERSION` | **Yes** | Exact version of the UI image. |

Change these through `upgrade.sh`, which keeps a history so `rollback.sh` can go back. See [Upgrades](/help/install/upgrades/).

### `secrets.env` (generated)

`provision.sh` creates these once, with random values, and keeps them on re-runs: `POSTGRES_OWNER_PASSWORD`, `POSTGRES_APP_PASSWORD`, `REDIS_PASSWORD`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `SESSION_SECRET`, `SETUP_TOKEN`. Keep a copy in your secrets store.

### Variables set in the shell

| Name | Used by | What it does |
| --- | --- | --- |
| `LIMS_BACKUP_DIR` | All scripts | Where backups are written, instead of `<company folder>/backups`. |
| `PROXY_SITES_DIR` | Proxy, `proxy-sync.sh` | Folder of proxy site files. Default `/srv/lims-proxy/sites`. |
| `LIMS_S3_ACCESS_KEY`, `LIMS_S3_SECRET_KEY` | `provision.sh` | Use these storage keys instead of generating new ones. |
| `LIMS_SKIP_BACKUP_CRON` | `provision.sh` | `true` skips installing the nightly backup. For throwaway checks only. |
